# 校园活动管理系统 V1.0 工程意图

## 1. 建设目的

建设校园活动管理系统 V1.0，是为了给活动组织教师和学生提供一个统一的活动发布与报名平台。

当前版本主要解决以下核心业务问题：

- 教师缺少统一的活动发布和管理方式。
- 学生不方便查看活动详情和报名活动。
- 学生报名后不方便查看自己的报名记录或取消报名。
- 教师不方便查看自己发布的活动有哪些学生报名。
- 活动报名需要受到重复报名、人数上限和活动结束状态的限制。
- 系统需要区分学生和教师的操作权限，保证活动管理范围正确。

V1.0 优先保证“教师发布活动 → 学生查看活动 → 学生报名 → 教师查看报名学生”的核心业务流程能够完整运行。

## 2. 本轮范围

### 2.1 本轮准备完成的内容

本轮 V1.0 包含以下已确定功能：

学生功能：

- 注册
- 登录
- 查看活动列表
- 查看活动详情
- 报名活动
- 查看我的报名
- 取消报名

活动组织教师功能：

- 登录
- 发布活动
- 查看自己发布的活动
- 修改活动
- 关闭活动
- 查看报名学生

本轮还需要保证以下核心流程能够运行：

1. 教师登录并发布活动。
2. 学生注册、登录并查看活动列表和活动详情。
3. 学生对符合条件的活动进行报名。
4. 教师查看自己发布的活动及报名学生。

### 2.2 本轮暂不实现的功能

V1.0 暂不实现以下功能：

- 签到
- 评论
- 消息通知
- 推荐算法
- 积分

除已经确定的学生功能、教师功能和基本业务规则外，本轮不增加其他功能。

## 3. 重要约束

1. **不能重复报名**：同一学生不能重复报名同一个活动。
2. **不能超过人数上限**：活动报名人数达到上限后，不能继续接受新的报名。
3. **已结束活动不能报名**：活动结束后，学生不能再提交报名。
4. **只有教师可以发布活动**：学生不能发布活动，只有活动组织教师可以发布活动。
5. **教师只能管理自己的活动**：教师只能查看、修改和关闭自己发布的活动，不能管理其他教师发布的活动。
6. **学生和教师权限不同**：学生只能使用学生相关功能，教师才能使用活动发布和管理相关功能；不同角色不能越权使用对方的功能。

## 4. 完成依据

V1.0 是否达到目标，应通过后续软件运行和测试验证以下实际结果：

1. 学生能够注册账号并登录，教师能够登录系统。
2. 教师发布活动后，学生能够在活动列表中看到该活动并查看详情。
3. 学生对未结束且未达到人数上限的活动报名后，系统能够记录报名结果。
4. 同一学生再次报名同一个活动时，系统拒绝重复报名，且不会产生第二条有效报名记录。
5. 活动报名人数达到上限后，新的报名请求被拒绝，已有报名人数不超过上限。
6. 学生报名已结束活动时，系统拒绝报名，且报名记录不会增加。
7. 学生能够查看自己的报名记录并取消自己的报名。
8. 教师能够查看自己发布的活动和报名学生，但不能管理其他教师发布的活动或查看其报名学生。
9. 学生不能执行教师的发布、修改和关闭活动操作，教师也不能使用学生身份查看或修改其他学生的报名记录。
10. 教师发布、学生查看、学生报名、教师查看报名学生这一核心业务流程能够连续完成。
