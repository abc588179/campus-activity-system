# 校园活动管理系统 V1.0 需求分析

## 1. 文档说明

本文档根据项目 README.md 中已确定的范围编写，用于明确校园活动管理系统 V1.0 的业务问题、用户目标、功能需求和范围边界。

V1.0 当前处于需求分析阶段，本阶段不涉及具体技术方案和业务代码实现。

## 2. 业务问题

当前校园活动的发布和报名管理需要一个统一的系统支持，主要存在以下业务问题：

1. 活动组织教师需要一个统一入口发布活动，并管理自己发布的活动。
2. 学生需要方便地查看可参加的活动及活动详情。
3. 学生报名后需要能够查看自己的报名记录，并在需要时取消报名。
4. 教师需要知道自己发布的活动有哪些学生报名。
5. 报名过程需要遵守基本业务规则，避免重复报名、超出人数上限或报名已结束的活动。
6. 活动发布和管理需要区分用户角色，确保只有教师能够发布活动，且教师只能管理自己发布的活动。

## 3. 用户目标

### 3.1 学生

学生的目标是：

- 注册并登录系统。
- 及时查看活动列表和活动详情。
- 选择符合条件的活动进行报名。
- 确认和查看自己的报名记录。
- 在需要时取消自己的报名。
- 在报名时得到重复报名、人数已满或活动已结束等规则的明确限制。

### 3.2 活动组织教师

活动组织教师的目标是：

- 登录系统开展活动管理工作。
- 发布活动并设置活动人数上限及活动结束信息。
- 查看自己发布的活动。
- 修改自己发布的活动。
- 在需要时关闭自己发布的活动。
- 查看自己发布的活动对应的报名学生。

## 4. V1.0 功能范围

V1.0 包含以下已经确定的功能：

### 学生功能

- 注册
- 登录
- 查看活动列表
- 查看活动详情
- 报名活动
- 查看我的报名
- 取消报名

### 活动组织教师功能

- 登录
- 发布活动
- 查看自己发布的活动
- 修改活动
- 关闭活动
- 查看报名学生

## 5. V1.0 需求定义

每条需求均包含需求编号、用户/角色、需求描述、优先级和验收依据。

优先级说明：

- **高**：核心业务流程必须实现，直接影响 V1.0 的主要业务闭环。
- **中**：V1.0 已确定需要实现的基础功能，但不单独构成核心业务闭环。
- **低**：当前文档没有单独定义为低优先级的 V1.0 功能，保留该等级用于后续需求分析时进行范围控制。

### REQ-01 学生注册

- **需求编号**：REQ-01
- **用户/角色**：学生
- **需求描述**：系统应支持学生注册账号，以便学生登录后使用活动查看、报名和报名记录相关功能。
- **优先级**：中
- **验收依据**：学生提交注册信息后能够成功创建账号，并能够使用该账号登录系统；注册失败时不应创建可用账号。

### REQ-02 学生登录

- **需求编号**：REQ-02
- **用户/角色**：学生
- **需求描述**：系统应支持学生登录，以便学生访问学生相关功能。
- **优先级**：高
- **验收依据**：学生使用已注册账号登录成功后，可以访问活动列表、活动详情、报名和我的报名；未登录学生不能直接使用需要身份的学生功能。

### REQ-03 教师登录

- **需求编号**：REQ-03
- **用户/角色**：活动组织教师
- **需求描述**：系统应支持活动组织教师登录，以便教师发布和管理自己组织的活动。
- **优先级**：高
- **验收依据**：教师登录成功后，可以访问活动发布、自己发布的活动和报名学生相关功能；未登录用户不能直接使用教师功能。

### REQ-04 查看活动列表

- **需求编号**：REQ-04
- **用户/角色**：学生
- **需求描述**：系统应向学生提供活动列表，供学生浏览当前系统中的活动。
- **优先级**：高
- **验收依据**：学生登录后能够打开活动列表，并看到系统中可查看的活动；列表中的活动能够进入对应的活动详情。

### REQ-05 查看活动详情

- **需求编号**：REQ-05
- **用户/角色**：学生
- **需求描述**：系统应向学生展示活动详情，供学生在报名之前了解活动信息、活动人数限制和活动结束情况。
- **优先级**：高
- **验收依据**：学生从活动列表进入某个活动后，能够查看该活动的详细信息、人数上限和结束状态，并据此判断是否可以报名。

### REQ-06 教师发布活动

- **需求编号**：REQ-06
- **用户/角色**：活动组织教师
- **需求描述**：系统应支持教师发布活动，并设置活动信息、活动结束信息和人数上限。
- **优先级**：高
- **验收依据**：已登录教师提交有效的活动信息后，活动能够成功发布，并出现在活动列表中；学生能够查看该活动详情。

### REQ-07 查看自己发布的活动

- **需求编号**：REQ-07
- **用户/角色**：活动组织教师
- **需求描述**：系统应支持教师查看自己发布的活动。
- **优先级**：中
- **验收依据**：教师登录后能够看到自己发布的活动；该列表不应把其他教师发布的活动作为其可管理活动展示。

### REQ-08 修改自己发布的活动

- **需求编号**：REQ-08
- **用户/角色**：活动组织教师
- **需求描述**：系统应支持教师修改自己发布的活动信息。
- **优先级**：中
- **验收依据**：教师能够修改自己发布的活动并保存，保存后的活动详情能够显示修改结果；教师不能修改其他教师发布的活动。

### REQ-09 关闭自己发布的活动

- **需求编号**：REQ-09
- **用户/角色**：活动组织教师
- **需求描述**：系统应支持教师关闭自己发布的活动，使该活动不再接受新的报名。
- **优先级**：中
- **验收依据**：教师关闭自己发布的活动后，该活动状态能够反映为已关闭，学生不能继续报名；教师不能关闭其他教师发布的活动。

### REQ-10 学生报名活动

- **需求编号**：REQ-10
- **用户/角色**：学生
- **需求描述**：系统应支持学生对符合报名条件的活动提交报名，并记录报名结果。
- **优先级**：高
- **验收依据**：学生对未结束且未达到人数上限的活动提交报名后，系统记录该学生的报名信息，并提示报名成功。

### REQ-11 防止重复报名

- **需求编号**：REQ-11
- **用户/角色**：学生
- **需求描述**：系统应阻止同一学生重复报名同一个活动。
- **优先级**：高
- **验收依据**：学生已成功报名某活动后再次报名同一活动，系统拒绝第二次报名，且该学生在该活动中仍只有一条有效报名记录。

### REQ-12 限制活动报名人数

- **需求编号**：REQ-12
- **用户/角色**：学生
- **需求描述**：当活动报名人数达到活动人数上限时，系统应阻止新的学生报名。
- **优先级**：高
- **验收依据**：活动报名人数达到上限后，新的报名请求被拒绝；活动已有报名人数不超过设定的上限。

### REQ-13 限制已结束活动报名

- **需求编号**：REQ-13
- **用户/角色**：学生
- **需求描述**：已结束的活动不能接受学生报名。
- **优先级**：高
- **验收依据**：学生对已结束活动提交报名时，系统拒绝报名；该活动的报名记录不会因本次操作增加。

### REQ-14 查看我的报名

- **需求编号**：REQ-14
- **用户/角色**：学生
- **需求描述**：系统应支持学生查看自己的报名记录，了解已经报名的活动。
- **优先级**：中
- **验收依据**：学生登录后能够查看自己的报名列表；列表只包含该学生的报名记录，不显示其他学生的报名记录。

### REQ-15 取消报名

- **需求编号**：REQ-15
- **用户/角色**：学生
- **需求描述**：系统应支持学生取消自己的活动报名。
- **优先级**：中
- **验收依据**：学生对自己已经报名的活动执行取消操作后，该报名不再作为自己的有效报名显示；学生不能取消其他学生的报名。

### REQ-16 教师查看报名学生

- **需求编号**：REQ-16
- **用户/角色**：活动组织教师
- **需求描述**：系统应支持教师查看自己发布的活动的报名学生。
- **优先级**：高
- **验收依据**：教师打开自己发布的活动后，能够查看该活动的报名学生；不能查看其他教师活动的报名学生。

## 6. 代表性需求取舍与范围控制

### 6.1 优先保证核心业务闭环

V1.0 优先实现教师发布活动、学生查看活动、学生报名、教师查看报名学生这一条核心流程，因此 REQ-02、REQ-03、REQ-04、REQ-05、REQ-06、REQ-10 和 REQ-16 标记为高优先级。其他已确定功能仍属于 V1.0，但安排为中优先级，避免核心流程被非核心功能分散。

### 6.2 保留报名规则，暂不扩展复杂业务

重复报名、人数上限和活动结束限制直接影响报名数据的正确性，因此纳入 V1.0 的高优先级需求（REQ-11、REQ-12、REQ-13）。本版本只实现 README.md 已确定的基本规则，不增加审批、候补名单、签到或通知等相关功能。

### 6.3 明确角色权限，控制管理范围

教师只能管理自己发布的活动，学生只能管理自己的报名记录。这一范围控制既满足当前业务需要，也避免 V1.0 引入管理员、跨教师协作或其他角色。系统暂不实现签到、评论、消息通知、推荐算法和积分功能。

## 7. V1.0 范围外功能

以下功能不属于当前版本需求：

- 签到
- 评论
- 消息通知
- 推荐算法
- 积分

除 README.md 已明确的功能和规则外，本需求文档不主动增加其他业务功能。
