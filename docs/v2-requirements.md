# 校园活动管理系统 V2.0 需求演化说明

本文件记录 V1.0 → V2.0 的需求来源、确认过程与权限边界，作为本轮设计、实现和测试的依据。

## 1. 需求来源

本轮不提供现成需求清单，需求来自三个角色的模拟访谈（学生、活动组织教师、系统管理员）。原始访谈记录见实验二实验报告。

访谈提炼出的关键事实：

| 来源 | 关键表述 | 提炼出的事实 |
| --- | --- | --- |
| 学生 | 「提交以后不能马上确定能不能参加，看不明白自己现在是什么情况」 | 报名后状态不可见 |
| 学生 | 「热门活动很快就满了，晚一点看到基本就报不上」 | 满员后无排队途径 |
| 教师 | 「学生临时不能参加时可以取消自己的报名」 | 学生需要自助取消能力 |
| 教师 | 「我得分清哪些人已经确定参加、哪些人还在候补」 | 名单必须分为两类 |
| 教师 | 「候补学生不想再等时可以退出，排在他后面的人按原顺序向前移动」 | 候补为 FIFO 队列，支持退出与前移 |
| 管理员 | 「可以查看全部活动，但不会代替教师处理具体报名」 | 管理员只读，不介入报名业务 |
| 管理员 | 「当前业务规则里没有明确这一项」 | 角色调整 / 账号停用不纳入本轮 |

## 2. 需求项

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| R1 | 报名记录增加状态（已确认 / 候补 / 已取消），学生可查看自己的状态 | 高 |
| R2 | 活动满员后报名转入候补，而不是直接拒绝 | 高 |
| R3 | 候补队列按报名先后排序，并支持自动递补 | 高 |
| R4 | 已确认学生可取消报名，取消后释放名额并触发递补 | 高 |
| R5 | 候补学生可退出候补，后续候补顺序前移 | 中 |
| R6 | 教师可编辑已发布活动 | 中 |
| R7 | 教师报名管理页同时展示已确认名单与候补名单 | 高 |
| R8 | 新增系统管理员，可只读查看全平台活动与用户账号 | 中 |
| R9 | 管理员不得处理报名业务、不得编辑活动、不得调整账号 | 高（约束） |

## 3. 角色权限边界

| 角色 | 允许 | 明确不允许 |
| --- | --- | --- |
| 学生 | 浏览活动、报名 / 候补、取消报名、退出候补、查看自己的报名状态与候补位置 | 发布活动、审批报名、查看其他学生报名、管理账号 |
| 活动组织教师 | 创建 / 编辑 / 关闭自己的活动、查看本活动的已确认与候补名单 | 查看其他教师的活动、管理账号、处理其他教师活动的报名 |
| 系统管理员 | 查看全平台活动、查看用户账号与状态 | 处理报名 / 候补、发布活动、编辑活动、调整报名状态、调整角色或停用账号 |

## 4. 对 V1.0 的影响

| 变更项 | V1.0 | V2.0 | 影响 |
| --- | --- | --- | --- |
| 报名状态模型 | `active` / `cancelled`，报名即占用名额 | `confirmed` / `waiting` / `cancelled` | 需迁移 `Registration` 表 |
| 候补队列 | 无 | 新增 `queue_order` + FIFO 递补 | 新增递补与前移逻辑 |
| 取消报名 | 无 | 新增 `/activities/<id>/cancel` | 新增路由与前端按钮 |
| 退出候补 | 无 | 新增 `/activities/<id>/waitlist/leave` | 新增路由与前端按钮 |
| 报名人数统计 | 统计 `active` | 统计 `confirmed`，另统计 `waiting` | 列表页与详情页需同时展示两个数 |
| 角色 | student / teacher | 增加 admin | `User.role` 约束扩展，新增 `@admin_required` 等价校验 |

## 5. 未纳入本轮

- 候补结果通知（需短信 / 邮件外部通道，V1.0 已明确不做消息通知）
- 管理员停用账号或调整角色（访谈中管理员明确表示业务规则未定义）
- 活动检索与筛选（V2.0 访谈未涉及，留待后续版本）
